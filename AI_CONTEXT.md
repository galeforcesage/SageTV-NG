### Commercial Detection (Comskip)

#### Two folders that sound alike but do different things

1. **`third_party/comskip/`** — vendored upstream **comskip C source**
   (originally a submodule of erikkaashoek/Comskip @ 0.83.001, converted
   to plain vendored files for build reliability). Used by `Dockerfile`
   for the source-build path. Do **NOT** re-register as a submodule.
   Do **NOT** delete.

   Note: `config.h` is correctly excluded by upstream comskip's own
   `.gitignore` (line 22, `config.*`) as it's an autotools build artifact
   regenerated by `./configure` during the source build.

2. **`comskip/`** (repo root) — our **profile INI files**:
   - `comskip_base.ini` — master config
   - `comskip_sports.delta.ini` — sports overlay
   - `comskip_news.delta.ini` — news overlay
   - `comskip_hdhomerun.delta.ini` — HDHomeRun-specific tuning

   Copied into `serverrelease/comskip_profiles/` by
   `build/copyserverfiles.sh` during release packaging.

#### Two ways comskip can run

1. **Source build (preferred for releases):** Docker compiles upstream
   comskip from `third_party/comskip/` and bundles the binary.
2. **Apt fallback:** If `third_party/comskip/` is empty, Docker skips
   the source build. Server uses OS-installed `comskip`
   (`apt install comskip` on Linux; user-provided `comskip.exe` on
   Windows). Historically used when GPU-driver incompatibilities
   broke the source-built binary on a specific device.

#### Profile system architecture

- "Sports / News / Default" are **content types**, not three separate
  full INIs. They use **base INI + content-specific delta overlays**.
- Toggled via STV: `IsCommercialDetectProfilesEnabled()` /
  `SetCommercialDetectProfilesEnabled(...)` (STV `COMSKIP-640..651`).
- Per-channel / per-show INIs go in an external directory configured
  via `GetComskipIniDirectory()` / `SetComskipIniDirectory()`. Drop
  `ShowName.ini` or `ChannelName.ini` files there for custom profiles
  outside the shipped overlays.

#### Integration code surface

- **Java:** `CommercialSkipAPI.java` (1190 inserts vs upstream),
  `CommercialDetectionManager.java` (singleton: launches comskip,
  manages concurrency, produces EDL output).
- **STV:** ~300 `COMSKIP-*` symbols in `stvs/SageTV7/SageTV7.xml`
  (settings, queue management, batch detection, on-screen commercial
  bar, indicators, per-recording menu actions).
- **Config:** Sage.properties keys under `commercial_detection/*`.

#### DOs and DON'Ts for AI tools

- ✅ Treat both `third_party/comskip/` and `comskip/` as intentional.
- ❌ Don't propose to "restore" `comskip/` files — they exist; just confirm.
- ❌ Don't propose top-level `sports.ini` / `news.ini` / `standard.ini`
  files. Profiles are `comskip_<type>.delta.ini` overlays inside `comskip/`.
- ❌ Don't reimplement comskip in Java; we delegate to the binary.
- ❌ Don't drop `third_party/comskip/`; the Dockerfile source-build path
  depends on it.
- ❌ Don't try to merge `comskip/` and `third_party/comskip/`; they are
  intentionally separate (profile assets vs upstream source).
- ❌ Don't try to add `config.h` to git — it's a build artifact, ignored
  by upstream comskip's own `.gitignore`.

## Phase 2 - Expression Caching

Phase 2 is split into two layers. The build-time layer lives in
`docs/STV_Cleanup/stv_cache_patcher.py` and is responsible for finding
repeated expensive Catbert expressions and emitting `SetLocal`/
`GetLocal` patch plans. The runtime layer is separate and still pending;
it must live in STV XML hooks and Java callbacks that invalidate cached
values on focus, selection, or setting changes.

AC-2.5 depends on that runtime layer, so patch generation alone is not
the finish line. Current status: build-time patch generation complete;
runtime invalidation hooks pending.
